# TSSE Editorial OS Data Model

## Purpose

This document defines the core entities managed by TSSE Editorial OS and the relationships between them.

The objective is to create a consistent representation of podcast episodes, guests, startups, newsletter issues, and community organizations so that editorial recommendations can be generated automatically while preserving human editorial judgment.

---

# Entity Relationships

```text
Episode
│
├── Guest
├── Themes
├── Founder Lessons
├── Community Organization
│
└── Newsletter Issue
      │
      ├── Connected Insight Guest
      ├── Startup Corner Startup
      └── Email Intro
```

---

# Episode

Represents a published TSSE podcast episode.

## Fields

```yaml

  episode_number:
  title:
  guest_name:
  publication_date:
  podcast_url:
  transcript_url:
  transcript_text:
```

## Derived Metadata

Generated through transcript analysis.

```yaml
analysis:
  primary_theme:
  secondary_themes:
  founder_lessons:
  notable_quotes:
  industries:
  keywords:
```

## Example

```yaml
episode:
  episode_number: 188
  guest_name: Ian Sandler

analysis:
  primary_theme: Leadership Through Human Connection
  secondary_themes:
    - Self Awareness
    - Relationship Building
    - Kind Leadership
```

# Theme

Represents a recurring concept discussed within the TSSE ecosystem.

Themes are extracted from transcripts and used for recommendation matching.

## Examples

```yaml

  name: Leadership

theme:
  name: Venture Capital

theme:
  name: Deep Tech

theme:
  name: Founder Resilience
```

## Purpose

Themes connect:

* Episodes
* Guests
* Startups
* Newsletter Issues

Themes form the foundation of recommendation logic.

# Connected Insight Recommendation

Represents a recommendation generated by the system.

## Fields

```yaml
recommendation:
  candidate_guest:
  similarity_score:
  rationale:
```

## Inputs

* Episode themes
* Guest rank database
* Newsletter history

## Constraints

* Guest must be Rank 4.
* Guest should not have been featured recently.
* Guest should align with the issue theme.

---

# Startup Recommendation

Represents a Startup Corner recommendation.

## Fields

```yaml
recommendation:
  candidate_startup:
  relevance_score:
  rationale:
```

## Inputs

* Episode themes
* Startup watchlist
* Recent startup developments
* Newsletter history

## Constraints

* Avoid recently featured startups.
* Prefer thematic alignment.
* Prefer recent developments.

---

# Email Intro

Represents a candidate newsletter introduction.

## Types

### Big-Idea Intro

Opens with a broad concept or question.

### Founder/Investor Commentary Intro

Opens with an observation about an industry trend or misconception.

### Personal Reflection Intro

Opens with a personal story or reflection connected to the issue theme.

## Fields

```yaml
intro:
  type:
  content:
```

Multiple intro options may be generated for each newsletter issue.

# Guiding Principle

The TSSE newsletter is built around ideas, not individuals.

Episodes, guests, startups, and community organizations are connected through themes.

All recommendation systems should prioritize thematic relevance before other factors.
